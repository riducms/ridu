# Ridu

This application was generated by Ridu. Its executable Go configuration is the source of truth.

This repository-owned playground deliberately follows the framework checkout instead of the
published release. Prepare it from the framework root before running it:

```sh
make playground-ridu-dev
```

The repository wrapper hydrates checkout dependencies and starts the playground's PostgreSQL on
port `54339`. After stopping Ridu with Ctrl+C, run `make playground-ridu-down` from the framework
root to stop the database container. To rehearse first-time setup again, run
`make playground-ridu-reset`; it deletes only this playground's PostgreSQL volume and content.

**New to Ridu? Start with [`PROJECT.md`](./PROJECT.md).** It explains what every generated file is
for, which files are yours to edit, and which files Ridu owns.

- Go module: `example.com/ridu-playground`
- Generated client: `generated/ridu.generated.ts`
- Ridu release: `v0.0.0-dogfood.1787424314091508000`

Ridu starts the development database, installs missing frontend dependencies, keeps generated
contracts current, runs the Go API and Vite admin together, and prints the local URLs. Edit
`content/*.go` to change your CMS. Schema changes reload the open admin after the new Go server is
ready; Svelte component changes use Vite hot module replacement.

On an empty database, open the admin and create the first `users` account in the guided setup
screen. Ridu serializes that anonymous first-user operation with the credential write, so exactly
one contender can succeed. Afterward, the starter Users and Posts policies require authentication;
anonymous registration is not enabled accidentally. See `PROJECT.md` for the non-interactive REST
shape and for how to opt into intentional public registration.

This migration playground also enables Ridu's optional GraphQL plugin. `ridu generate` writes its
exact compiled schema to `generated/ridu.graphql`; use that committed SDL for GraphQL client
generation, editor validation, and migration comparisons without enabling network introspection.

Before release:

```sh
ridu migrate create --name initial
ridu generate --check
ridu check
ridu migrate verify
ridu build
```

The production artifact is `dist/ridu`. Production needs only that binary and its
environment variables; Bun and Node are build-time dependencies. Inspect `ridu migrate plan --json`
and apply `ridu migrate up` with the exact release and committed artifacts before starting the new
binary. Follow the production boundary and cutover checklist in `PROJECT.md`.

If `ridu new` retained this project after dependency or generation setup failed, fix the reported
error and finish initialization with `go mod tidy && ridu generate` before starting development.
